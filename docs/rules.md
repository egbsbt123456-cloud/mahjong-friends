# 麻将（广东麻将，好友房）规则与实现说明

> 本文件来自原桌游平台的规则文档。在这个独立仓库里有几处不同：数据库是**迁移 1**（文中「迁移 11」指平台里的编号，表结构相同）；文中提到的大厅卡片、游戏目录、平台房间清理表在这里不存在；端口为 3020 / 5190。

> 状态：定稿（2026-11-22），已实现。
> 网站显示名：**麻将**；路由 `/games/mahjong-gd`；游戏标识 `mahjong-gd`；规则版本 `gd-1.0`。
> 只做 4 人好友房。没有积分、番数、倍数、马牌、排行、观战、匹配、人机对战、同屏。

## 1. 牌

### 1.1 牌的编码

| 编码 | 牌 | 每种张数 |
|---|---|---|
| `m1`–`m9` | 一萬–九萬 | 4 |
| `p1`–`p9` | 一筒–九筒 | 4 |
| `s1`–`s9` | 一条–九条 | 4 |
| `z1`–`z4` | 東、南、西、北（风牌） | 4 |
| `z5`–`z7` | 中、發、白（箭牌） | 4 |
| `f1`–`f8` | 春夏秋冬梅蘭竹菊（花牌） | 1 |

每张实体牌另有唯一编号 `id`（0–143），前端只用 `id` 指定要出的牌，防止「同名牌」出错。

### 1.2 牌组（由两个开关决定）

| 字牌 | 花牌 | 牌组 |
|---|---|---|
| 关 | —（变灰） | 108 张：万条筒 |
| 开 | 关 | 136 张：+ 東南西北中發白 |
| 开 | 开 | 144 张：+ 8 张花牌 |

### 1.3 牌面素材
平台自己用 SVG 画（`apps/web/src/games/mahjong/tiles.ts`，由样板 `tmp/mj/tiles.js` 改成 TS），象牙色牌面，墨绿色牌背加网站图标。鬼牌右上角显示金色「鬼」标记，庄家显示「莊」字圆章。没有音效。

## 2. 房主设置

开局前只有房主能改；**改任何设置都会取消所有人的「准备」**。开局后锁定，「再来一局」沿用上一局设置，房主可以在等待阶段再改。

| 分组 | 设置项 | 可选值 | 默认 |
|---|---|---|---|
| 牌组 | 字牌 | 开 / 关 | 开 |
| | 花牌 | 开 / 关 | 关 |
| 吃碰杠 | 吃 | 开 / 关 | 开 |
| | 碰 | 开 / 关 | 开 |
| | 明杠 | 开 / 关 | 开 |
| | 暗杠 | 开 / 关 | 开 |
| | 补杠 | 开 / 关 | 开 |
| 胡牌方式 | 自摸胡 | 开 / 关 | 开 |
| | 点炮胡 | 开 / 关 | 开 |
| | 抢杠胡 | 开 / 关 | 开 |
| 鬼牌 | 鬼牌 | 无鬼 / 红中鬼 / 翻鬼 | 无鬼 |
| 牌型 | 鸡胡、平胡、碰碰胡、七小对、十三幺、清一色、混一色、大三元、小三元、大四喜、小四喜、天胡、地胡 | 每项 开 / 关 | 全开 |
| 计时 | 每步限时 | 15 / 30 / 60 秒 | 30 秒 |

### 2.1 开关之间的限制（前后端都校验，服务器以自己为准）

1. **字牌关** → 以下几项强制关闭并变灰：花牌、十三幺、大三元、小三元、大四喜、小四喜、混一色、红中鬼（鬼牌只能选无鬼 / 翻鬼）。
2. **自摸胡、点炮胡至少开一个**，两个都关时不能保存。
3. **抢杠胡**只有在「补杠」开着时才能开（只能抢补杠），补杠关掉时变灰。
4. **点炮胡关**时，抢杠胡也自动关闭（抢杠属于胡别人的牌）。
5. **鸡胡关**时，下列「能成为胡牌条件」的牌型至少要开一个：平胡、碰碰胡、七小对、十三幺、清一色、混一色、大三元、小三元、大四喜、小四喜。否则不能保存（天胡、地胡不算，它们只是时机，不是牌型）。
6. 设置不合法时服务器返回 400，并给出中文原因。

## 3. 一局流程

```
建房 → 房主设置 → 四人到齐并准备 → 发牌 → 补花 → （翻鬼）→ 庄家出牌
→ 摸牌 / 出牌 / 吃碰杠胡循环 → 有人胡 或 牌墙摸完流局
→ 亮出所有手牌、显示胡法和牌型 → 再来一局（四人重新准备）
```

### 3.1 座位与庄家
- 座位 0–3，逆时针（下家 = 座位 +1）。界面上自己永远在下方。
- **第一局随机定庄**。之后：庄家胡 → 连庄；别人胡 → 庄家的下家做庄；流局 → 庄家不变。
- 房间关闭或有人退出再加入，算重新开始，重新随机定庄。

### 3.2 发牌
- 服务器用加密随机数洗牌，牌墙顺序只保存在服务器，不下发。
- 庄家 14 张，其他人 13 张。
- 正常摸牌从**牌头**取；杠后补牌、补花从**牌尾**取。

### 3.3 补花（只在花牌开时）
- 发完牌后，从庄家开始按座位顺序，每人把手里的花牌全部亮出，从牌尾补同样张数；补到的又是花就继续补，直到没有花。
- 对局中摸到花牌：自动亮出、从牌尾补一张，然后照常行动。
- 花牌**没有任何作用**，只亮在座位旁边，不影响胡牌。补花不算「吃碰杠」，不影响天胡、地胡。

### 3.4 翻鬼（只在鬼牌 = 翻鬼时）
- 补花完成后，从**牌尾**翻开一张作为「翻牌」，公开显示，这张牌离开牌墙，谁也摸不到。翻到花牌则放到一边再翻一张。
- 鬼牌 = 翻牌的**下一张**，这种牌的 4 张都是鬼：
  - 万、条、筒：同花色加一，九之后是一（九萬 → 一萬）。
  - 风牌：東 → 南 → 西 → 北 → 東。
  - 箭牌：中 → 發 → 白 → 中。
- 红中鬼：4 张「中」是鬼。

### 3.5 鬼牌的用法
- 在胡牌判定时可以当作**任意一张牌**，包括七小对、十三幺。
- 可以被打出去。**打出去的鬼按牌面算**，就是一张普通的牌：别人可以照常吃、碰、明杠、胡它；胡这张牌时它只当牌面本身，不再是万能牌。
- 被吃、碰、杠进牌组的鬼也只按牌面算。
- 手里的鬼**可以按牌面本身**参与吃、碰、明杠、补杠（例：红中鬼时，手里 2 张红中可以碰别人打出的红中）；但**不能当别的牌**去凑顺子、刻子。
- 4 张鬼不能暗杠。
- **没有**「四鬼直接胡」。

### 3.6 自己回合（摸牌后）
可以做的事：
1. **自摸胡**（自摸胡开着，并且手牌能胡）。
2. **暗杠**：手里有 4 张相同的牌（4 张鬼不能暗杠；鬼按牌面本身可以参与补杠）。
3. **补杠**：已经碰过的牌，又摸到或手里有第 4 张。
4. **出牌**：打出 1 张。

杠完从牌尾补一张，再回到第 3.6 步（杠后可以继续杠、自摸或出牌）。杠后补牌直接胡，称为**杠上开花，算自摸**。
牌墙剩 0 张时不能杠。

### 3.7 别人出牌后的响应
出牌后，服务器算出每个人可以做什么，只问有选项的人：

| 操作 | 条件 |
|---|---|
| 胡（点炮） | 点炮胡开着；能胡；不在过胡状态 |
| 碰 | 碰开着；手里有 2 张和它牌面相同的牌（鬼按牌面本身也算，不能当别的牌） |
| 明杠 | 明杠开着；手里有 3 张同牌；牌墙还有牌 |
| 吃 | 吃开着；**只能吃上家**；手里有能和它连成顺子的 2 张（鬼只按牌面本身算，不能当别的牌）；有几种吃法就列几种 |
| 过 | 永远可以 |

- **响应窗口最多 10 秒**（每步限时比 10 秒短时，按每步限时）。所有有选项的人都选了，立刻结算，不等满。
- 响应窗口超时**只算「过」，不进托管**（别人出牌时没看手机很常见）。
- 优先级：**胡 > 碰 / 明杠 > 吃**。
- 多人选胡：只算**离出牌者最近**的一个（按出牌者下家、对家、上家的顺序），其他人的胡作废。
- 低优先级的人先选了也要等高优先级的人选完；高优先级的人选「过」后，再看低优先级。
- 都过：出牌者的下家摸牌。
- 吃、碰后：吃碰的人**不摸牌**，直接出一张。明杠后：从牌尾补一张，进入第 3.6 步。

### 3.8 抢杠胡
- 只有**补杠**能被抢。有人补杠时，其他人如果能胡这张牌（抢杠胡开着、不在过胡状态），会有 10 秒「胡 / 过」。
- 有人抢：补杠作废，那张牌算胡牌者胡的牌，补杠者是点炮的人，其他人负。多人抢只给离补杠者最近的。
- 都过：补杠成立，补杠者从牌尾补牌。

### 3.9 过胡
- 能胡别人打出的牌（或抢杠）却选了「过」（含超时、托管自动过），在**自己下一次摸牌之前**，都不能再胡别人的牌（点炮和抢杠都不行）。
- 自摸不受影响。自己摸牌后过胡解除。

### 3.10 流局
- 轮到某人摸牌时牌墙已经没牌 → 流局，**平局**，没有胜者。
- 最后一张牌打出后照常给响应窗口（可以胡、碰、吃；不能杠，因为没牌补）。碰或吃后照常出牌，再轮到摸牌时流局。

### 3.11 胜负
| 结果 | 胜 | 负 |
|---|---|---|
| 自摸（含杠上开花） | 自摸者 | 其他 3 人 |
| 点炮 | 胡牌者 | 其他 3 人（显示谁点炮） |
| 抢杠 | 胡牌者 | 其他 3 人（显示谁被抢） |
| 流局 | — | 平局 |
| 四人都托管 60 秒后房间关闭 | — | 本局作废，无胜者 |

杠没有任何奖惩。所有允许的牌型地位相同，不比大小。

### 3.12 结束画面
- 亮出四家所有手牌、吃碰杠、花牌，牌墙剩余张数，鬼牌。
- 显示：谁胜、胡法（自摸 / 点炮 / 抢杠 / 杠上开花）、胡的那张牌、**满足的全部已开启牌型**（例如「碰碰胡 · 混一色」；只满足鸡胡就显示「鸡胡」），点炮或被抢杠的人。
- 「再来一局」：四人重新准备后开始，庄家按 3.1 处理。

## 4. 胡牌判定

### 4.1 能胡的牌形
手牌（含吃碰杠的牌组）满足下面任意一种，并且这种牌形是允许的：

| 牌形 | 说明 | 何时允许 |
|---|---|---|
| 标准形 | 4 组 + 1 对。组 = 顺子（同花色连续三张，字牌不能成顺）或刻子（三张相同），杠算刻子 | 鸡胡开：任何标准形都能胡；鸡胡关：还要满足至少一个已开的牌型 |
| 七小对 | 7 个对子，手上没有吃碰杠 | 七小对开 |
| 十三幺 | 一九萬、一九筒、一九条、東南西北中發白各一张，再加其中任意一张成对，没有吃碰杠 | 十三幺开（需要字牌） |

四张相同的牌在七小对里算 2 对。

### 4.2 牌型定义（用于「鸡胡关」时的条件，以及结束画面显示）

| 牌型 | 定义 |
|---|---|
| 鸡胡 | 任意标准形 |
| 平胡 | 标准形，4 组都是顺子（含吃的） |
| 碰碰胡 | 标准形，4 组都是刻子或杠 |
| 七小对 | 见 4.1 |
| 十三幺 | 见 4.1 |
| 清一色 | 全部牌（含吃碰杠）同一种花色，没有字牌；任何牌形都可以 |
| 混一色 | 只有一种花色加字牌，两者都要有；任何牌形都可以 |
| 大三元 | 标准形，中、發、白三组刻子或杠 |
| 小三元 | 标准形，中發白其中两组刻子或杠，第三种做将（对子） |
| 大四喜 | 标准形，東南西北四组刻子或杠 |
| 小四喜 | 标准形，三种风牌刻子或杠，第四种做将 |
| 天胡 | 庄家用发牌后的第一手牌自摸（补花之后、出第一张牌之前），且没有暗杠 |
| 地胡 | 闲家在自己第一次出牌之前胡牌（胡庄家打出的第一张，或自己第一次摸牌自摸），且这之前没有任何人吃、碰、杠 |

- 天胡、地胡是「时机」类牌型：开着时满足就显示；**它们本身不能代替牌形**，手牌仍需满足 4.1。
- 鸡胡关、只开了天胡时也不能胡（第 2.1 节第 5 条已禁止这种设置）。
- 带鬼时：只要存在一种把鬼替换成某些牌的方式，使手牌满足某个允许的牌形 / 牌型，就能胡。结束画面显示能满足的**最多**已开启牌型（只是显示，不影响胜负）。
- 「打出的鬼按牌面算」不影响自己手里的鬼。

### 4.3 判定实现
- 引擎：`packages/game-core/src/mahjong-gd-engine.cjs`（UMD，浏览器和服务器同一份，测试核对逐字一致，同斗兽棋做法）。
- 算法：手牌按 34 种计数 + 鬼数，回溯拆组（先拆将，再从最小牌开始拆刻子 / 顺子，鬼补缺），七小对、十三幺单独判定。只有 14 张，速度没问题。
- 前端不放引擎副本：能胡、能碰、能杠等按钮全部来自服务器下发的 `game.legal`，判定只在服务器做。

## 5. 计时与托管

### 5.1 每步计时
- 必须计时，房主选 15 / 30 / 60 秒。计时由服务器按截止时间判断，前端只显示倒计时。
- 「一步」= 自己回合要出牌（含摸牌后、吃碰后、杠后补牌后）。响应窗口用第 3.7 节的 10 秒。

### 5.2 托管
- 自己回合**超时** → 该座位进入**托管**：
  - 本步：能自摸也不胡、不杠，**打出刚摸到的那张**；吃碰后超时（没有刚摸的牌）打出手里最右边的一张（排序后最后一张）。
  - 之后每次轮到它：**立即**打出刚摸的牌；所有响应一律「过」，不吃、碰、杠、胡。
  - 托管座位的行动由服务器直接做，不等计时。
- 响应窗口超时只当作「过」，**不进入托管**。
- 页面在该座位头像上显示「托管中」，本人画面显示大按钮 **「我回来了」**。
- **只有点「我回来了」才收回**；刷新、断线重连都不会自动收回。收回后从下一步开始自己操作。
- 没有「断线重连」开关；断线就是不操作，按超时处理。

### 5.3 四座都托管
- 四个座位全部托管时开始 60 秒倒计时（所有人页面都显示）。
- 60 秒内任何人点「我回来了」→ 取消倒计时，继续。
- 60 秒到 → **关闭房间，本局作废，没有胜者**。
- 托管座位之间互相打牌会很快，为避免一局瞬间打完：托管座位每次行动间隔 **1 秒**（只用于显示节奏，不影响规则）。

## 6. 隐藏信息
每个人从服务器拿到的状态只包含：
- 自己的手牌（带 `id`）；别人的只有手牌张数。
- 所有人的吃碰杠、花牌、弃牌河（公开）。暗杠：别人只看到 4 张牌背（结束时公开）。
- 牌墙剩余张数（不含顺序）。
- 鬼牌和翻牌（公开）。
- 自己当前能做的操作列表（别人能做什么不下发；只显示「等待其他玩家响应」）。
- 结束后公开四家全部手牌和暗杠。

## 7. 服务器实现（照现有游戏统一写法）

- 文件：`apps/server/src/games/mahjong-gd.ts`，接口前缀 `/api/mahjong-gd`。
- 登录 Cookie `board_session`、Origin 校验、限流 60 次/分、数据库事务、`requestId` + 指纹幂等、`expectedVersion` 版本号防冲突；客户端 1.2 秒轮询。
- 数据库迁移 **11**（已实现）：
  - `mahjong_rooms`：房间码、房主座位、房间状态、规则设置 JSON、整局状态 JSON（含牌墙和操作记录，只在服务器读取）、局数、庄家、版本号、时间。
  - `mahjong_seats`：座位、用户、准备、`last_seen`（只用来显示在线）。
  - `mahjong_requests`：`requestId` + 指纹，防重复提交。
  - 原先设想的单独「每局状态表」「操作记录表」合并进了 `mahjong_rooms.state`（同平台其它卡牌游戏的做法）。
- 房间状态：`waiting`（等人、准备、改规则；**一局结束后也回到 waiting**，保留上一局结果用来展示，四人重新准备就是再来一局）、`playing`、`cancelled`（房主取消、人走光、四座托管 60 秒）。
- 服务器每秒检查一次到期计时；到期时间存在数据库里。**服务重启**后，停机前开的对局，到期时间至少顺延到启动后 15 秒，避免停机期间所有人被判超时托管。
- 有人加入或离开：重新随机定庄，清掉上一局结果。房主离开时房主转给座位号最小的人。

### 7.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/mahjong-gd/rooms` | 我参加的房间（最多 6 个，不含已取消） |
| POST | `/api/mahjong-gd/rooms` | 建房 `{settings?}`（房主坐 0 号位），返回房间视图 |
| GET | `/api/mahjong-gd/rooms/:code` | 取自己视角的状态（同时记一次在线心跳、处理到期计时） |
| POST | `/api/mahjong-gd/rooms/:code/join` | 加入空座位 |
| POST | `/api/mahjong-gd/rooms/:code/actions` | 所有操作，统一带 `requestId`、`expectedVersion` |

`actions` 的 `type`：

| type | 附加字段 | 何时可用 |
|---|---|---|

### 7.3 状态结构（服务器内部，示意）

```ts
type Tile = { id: number; code: string }        // code 如 'm5'
type Meld = { kind: 'chi' | 'pong' | 'exposedKong' | 'concealedKong' | 'addedKong';
              tiles: Tile[]; from?: Seat }       // from = 被吃碰杠的座位
interface HandState {
  rulesVersion: 'gd-1.0'
  settings: Settings
  dealer: Seat
  wall: Tile[]          // 牌头在前；只在服务器
  ghost: string | null  // 鬼牌 code
  indicator: Tile | null
  seats: Array<{ hand: Tile[]; melds: Meld[]; flowers: Tile[]; river: Tile[];
                 hosted: boolean; passedWinUntilDraw: boolean; hasDiscarded: boolean }>
  phase: 'turn' | 'response' | 'robKong' | 'finished' | 'void'
  turn: Seat
  lastDrawn: Tile | null
  lastDiscard: { seat: Seat; tile: Tile } | null
  pending: Record<Seat, Option[] | Choice>   // 响应窗口里各人的选项和已选
  deadline: number                            // 毫秒时间戳
  anyClaimHappened: boolean                   // 地胡判定用
  result?: Result
}
```

引擎是纯函数：`createHand(settings, dealer, rng)`、`legalActions(state, seat)`、`applyAction(state, seat, action)`、`onTimeout(state, now)`、`viewFor(state, seat)`、`analyzeWin(tiles, melds, ghost, settings)`。
